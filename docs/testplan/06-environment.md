## 6. Test Environment

**Hardware**

- Team laptops (Windows 11, 8 GB RAM or more) for development and functional testing
- One test server / VM: 2 vCPU, 4 GB RAM, 40 GB disk, Ubuntu 22.04 (also used for performance tests)
- One Android phone and one iPhone (or browser device emulation at 360 px) for responsive and usability tests

**Software**

- HAPRS v1.0 build from `main`, deployed with Docker Compose (Nginx, FastAPI backend, React frontend, PostgreSQL 15)
- Python 3.11, Node.js 20
- MailHog as the SMTP server so that every email can be inspected
- Supported browsers: latest Chrome, Edge and Firefox

**Tools**

| Purpose | Tool |
|---|---|
| Unit and integration tests | Pytest, pytest-cov |
| API tests | Postman / Newman |
| UI end-to-end tests | Playwright |
| Performance | Locust |
| Security | OWASP ZAP, testssl.sh |
| CI | GitHub Actions |
| Defect tracking | GitHub Issues (labels: `bug`, `severity:critical/high/medium/low`) |

**Test data (synthetic only — no real patient data)**

- 4 role accounts for manual testing (one per role) plus 20 Patient accounts for concurrency tests
- 20 doctors in 6 specializations with weekly availability; 200 patients with made-up names, phone numbers and allergies
- A large data set for TC-PERF-01: 500 doctors, 10,000 patients, 50,000 appointments, generated by a seed script
- Seed scripts are kept in the repository so the database can be reset before each test cycle
