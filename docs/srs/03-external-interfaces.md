## 3. External interface requirements

### 3.1 User interfaces

The primary UI is a responsive web application. Each role sees a home screen with only its own menu:

- **Patient:** Find a doctor → choose date → pick a slot from a colour-coded grid (free / unavailable) → confirm; My appointments (reschedule, cancel); My records (visits, prescriptions, PDF download); Profile; Notifications.
- **Doctor:** Today's schedule (time, patient, status), patient chart with allergies highlighted at the top, consultation form (symptoms, vitals, diagnosis, notes), prescription form with one row per medicine, Availability and Leave screens.
- **Receptionist:** Patient search and registration, booking on behalf of a patient, today's arrivals list with a one-click Check-in button.
- **Admin:** Staff accounts, doctor profiles, dashboard, report export.

Accessibility: WCAG 2.1 AA colour contrast, full keyboard navigation, form labels readable by screen readers, and minimum 16 px body text. Every error message states what went wrong and how to fix it (for example "This slot was just booked by someone else. Please pick another time.").

### 3.2 Hardware interfaces

No special hardware is required. Users need a desktop, laptop, tablet or smartphone with a modern browser. The front desk may use any printer supported by the operating system to print prescription PDFs. The server runs on standard x86-64 hardware or a cloud virtual machine with at least 2 vCPUs and 4 GB RAM.

### 3.3 Software interfaces

| Interface | Purpose | Protocol / format |
|---|---|---|
| PostgreSQL 15 | Stores users, patients, doctors, slots, appointments, records, audit log | SQL via SQLAlchemy over TLS |
| SMTP email gateway | Sends confirmations, cancellation and leave notices, 24-hour reminders | SMTP with STARTTLS |
| ReportLab PDF library | Generates prescription PDFs on request | In-process Python library |
| APScheduler | Runs nightly slot generation, reminder jobs and no-show marking | In-process scheduler |
| Swagger / OpenAPI | Machine-readable API description generated by FastAPI | OpenAPI 3 JSON at `/docs` |

### 3.4 Communications

- All client–server traffic uses HTTPS with TLS 1.2 or higher; HTTP is redirected to HTTPS (HAP-SR-003).
- The API is REST with JSON bodies under the base path `/api/v1`; requests carry `Authorization: Bearer <JWT>`.
- Errors use one body format: `{ "error": { "code": "STRING_CODE", "message": "Readable message" } }`.
- Email is sent asynchronously; a failed send is retried 3 times at 5-minute intervals and never blocks the user's request.
